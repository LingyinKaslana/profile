# CUDA 并行计算：Blelloch Scan 与鸟群仿真

> 一个把前缀和从 O(n log n) 做到 O(n)，一个把 16,384 只鸟的仿真从 0.5 fps 做到 45+ fps。

## 一、Stream Compaction：从倍增到 Blelloch Scan

- **问题**：把数组里的 0 去掉。第一步生成 0/1 标记、第三步按下标 scatter，都天然可并行，瓶颈全在第二步——求前缀和。
- **倍增版**：两个 buffer 滚动，第 d 轮执行 `odata[i] = idata[i-d] + idata[i]`，复杂度 O(n log n)。N = 2²⁰ 时，不考虑拷贝已经和 CPU 持平。
- **Blelloch 版**：上扫建树（区间和）+ 下扫还原前缀和，原地完成，O(n)；n 不是 2 的幂就向上补齐，跨 block 就切段再拼回去。
- **三项优化**：
  - 线程聚集：把 `(i + 1) % 2d == 0` 换成 `i < n / 2 / d`，让活跃线程集中到低编号，减少 warp 分歧，同时只需要 n/2 个线程；
  - 共享内存：block 内的数据搬进 shared memory，减少全局内存往返；
  - 消除 bank conflict：用 `idx + (idx >> 5)` 把访问错开，共享内存多开 1/32。
- **结果**：内核耗时快于 CPU，三项优化逐项验证都有收益。

## 二、鸟群仿真：0.5 fps → 45+ fps

- **规则**：每只鸟看邻居——聚拢（朝邻居中心）、避让（太近就反向）、对齐（速度趋向邻居均值）。
- **朴素版**：每个线程遍历全部 n 只鸟，O(n²)，16,384 只鸟在笔记本的 GeForce 450 上只有 0.5 fps。
- **均匀网格**：空间切成 B³（B = 32），格子边长取 `max(包围盒边长 / B, 邻居半径)`，每只鸟只枚举 27 个相邻格子 → 约 20 fps；但鸟飞散后格子疏密不均，帧率掉到 10 以下。
- **非均匀网格**：按 x / y / z 排序，按点数把 B 段切开（每段约 n/B），不再依赖空间分布均匀 → 稳定在 30–35 fps。
- **B 提到 256**：格子更细、每格更空，但 B³ 的数据从 CPU 搬到 GPU 太贵；改成只传非空格子的增量（UpdateBox / ClearBox 在 GPU 侧改），并把所有数组塞进一块连续 buffer，一次 memcpy 搞定。
- **两个附带优化**：线程 id 按格子排序后再映射，让同一 warp 落在同一格，减少分歧（实测约 2×）；kernel 之间不急着同步，CPU 准备下一帧、GPU 继续算，形成流水。
- **结果**：45+ fps。
